프레임워크 루트: `C:\Users\Administrator\.claude\loan-review\심사평가표프레임워크` (이하 `FW`)

산출물 폴더: `C:\Users\Administrator\Desktop\징쇼우(백업要)\회사AI작업\론리뷰` (이하 `OUT`) — 완성본(.docx·.pdf)만 `OUT/<케이스폴더명>/`에 복사한다. 프레임워크(FW)는 Claude 보관용이라 사용자가 열 일이 없다. `OUT`이 없으면(사용자가 옮겼으면) 새 위치를 묻고 이 줄을 고친다.
계산·docx 헬퍼·학습 로직은 `검토의견서프레임워크`(loan-review-1)을 재사용한다. 산식을 새로 만들지 않는다.

## 0. 읽기 순서 (토큰 절약 — 항상 전부 읽지 않는다)
- **항상**: `FW/rules/01_작성규칙.md` (1쪽/2쪽 항목별 규칙)
- **질문 단계에서**: `FW/rules/03_질문목록.md`
- **필요할 때만**:
  - `FW/rules/02_문구_라이브러리.md` — 조항·승인조건 문구를 찾거나 새로 추가할 때
  - `FW/rules/04_샘플오류노트.md` — 결재본 숫자와 계산이 어긋날 때(결재본 오타 이력)
  - `FW/rules/05_유형별_사례집.md` — 임대업·전결권 상향 등 특수 건일 때. 후보 조항을 꺼내 **해당 여부를 묻는다**(그대로 넣지 않음)

## 절대 규칙
- **숫자는 `sheetcalc.py` 결과만 쓴다.** 대출가능금액·금리 가산·이자수익·편중을 손으로 계산하지 않는다.
- **질문 전에 문서를 만들지 않는다.** `build.py`는 A등급 누락이 있으면 멈춘다. `--draft`는 사용자가 "일단 초안"이라 할 때만.
- 조항·조항번호는 **받은 자료에 적힌 그대로** 쓴다. 의심스러우면 그때 질문한다.
- 낙찰통계는 **넣지 않는다**(사용자가 별도 첨부).
- 기대출이 **6건 이상이면 자금용도가 같은 계좌끼리 묶어** 합산금액·최대금리로 표시한다(`merge_loans`가 자동 처리).
- 결과물은 **2쪽**(1쪽 평가표, 2쪽 요약표)이다. 쪽수가 늘면 내용이 넘친 것이므로 보고한다.

## 절차

### 1. 재료 읽기
첨부 자료를 전부 읽고 종류를 표로 보여준다(여신신청·금리산출 화면·감정평가서·신용평가·소득/재산세 증명·인포케어 캡처·등기부).
- `.hwp`는 읽지 못한다 → PDF로 요청.
- 스캔·사진이면 금액·점수·요율을 두 번 읽어 대조한다.

### 2. sheet.json 초안
- `FW/cases/<YYMMDD>_<채무자>/sheet.json`을 `FW/cases/_template/sheet.json`에서 복사해 채운다.
- 금액은 **원** 단위. 기대출 잔액도 원(표에서 천원으로 자동 환산된다).
- **금리는 기준금리·원가가산·우대내역을 모두 넣는다.** 그래야 가산금리가 검산된다.
- 평가표 칸은 표준값이면 비워둔다(자동으로 `적정`/`해당없음`/`부`가 들어간다).

### 3. 작성 전 질문
```
python "FW/scripts/sheetcalc.py" "<sheet.json>" --gaps
python "FW/scripts/sheetcalc.py" "<sheet.json>"        # 숫자 미리보기
```
- 핵심 숫자(대출가능금액·가산금리·이자수익)를 먼저 3줄로 보여준다.
- A·B는 번호 목록으로, D는 `AskUserQuestion`으로 묻는다(특인 유무, 승인조건, 기타 특이사항).
- `READY`가 뜰 때까지 반영하고 다시 돌린다.

### 4. 작성과 검수
```
python "FW/scripts/build.py" "<sheet.json>"
python "C:\Users\Administrator\.claude\loan-review\검토의견서프레임워크\scripts\to_pdf.py" "<생성된 .docx>"
```
- PDF를 열어 2쪽인지, 표가 깨지지 않았는지 확인한다.
- 보고: 파일 경로 / 핵심 수치 / 남은 검산 경고 / 미확보 항목.

### 5. 학습 (건이 쌓일수록 진화)
- 결재 최종본을 받으면 반드시 기록한다.
  ```
  python "FW/scripts/learn.py" record "<case_dir>" "<결재최종본.docx|.pdf>"
  python "FW/scripts/learn.py" candidates
  ```
- `FW/learning/candidates.md`에 2건 이상 반복된 수정이 올라온다. 사용자가 승인하면 그때 `rules/*.md`를 고치고 `learn.py close <id> approved`로 닫는다.
- **규칙을 스스로 바꾸지 않는다.** 과최적화 방지 — loan-review-1과 같은 원칙.
- 결재본이 스캔 이미지/사진이면 learn.py 대신 손으로 대조한다: 케이스 폴더에 사진 저장 → 초안 sheet.json을 `sheet_초안<날짜>.json`으로 보존 → 결재본대로 sheet.json 재작성·build로 재현 확인 → `learning/<채무자>_결재본대조.md` 작성 → 새 문구·조항은 02, 문체는 01, 특수 규정 조합은 05에 쌓는다(차주10 2026-10-20 방식).
